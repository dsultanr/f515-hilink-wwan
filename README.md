# F515 — подключение USB-модема и настройка приоритета сети через ADB

Инструкция для тех, у кого нет доступа к голове ничем, кроме `adb shell`. Только
физическое подключение модема + голые ADB-команды. Без установки чего-либо на
устройство, без WireGuard/туннеля — просто чтобы голова реально пользовалась
модемом как интернетом (а не считала, что интернета нет).

## Что и зачем

Штатный TBOX из машины физически выпилен, но Android продолжает держать для него
"призрачную" сотовую сеть (`vlan72`, gw/DNS `192.168.72.1`), которая никогда не
провалидируется и мешает считать модем нормальным интернетом. USB-модем сам по
себе поднимается и маршрутизируется нормально — не хватает только DNS для этой
призрачной сети, чтобы Android посчитал, что интернет есть, и NTP/приложения
заработали.

## 1. Физическое подключение модема

- Модем: **ZTE MF833R** (USB, HiLink-режим, VID:PID `19d2:1405`), MAC-адрес сетевого
  интерфейса `34:4b:50:00:00:00`.
- Просто вставить в любой USB-порт головы. Модем сам делает NAT+DHCP на своей
  стороне (HiLink), Android дальше получает адрес обычным DHCP-клиентом.
- Модем виден системе как **cdc_ether**-интерфейс — на этой прошивке это `eth1`
  (плюс появляется CD-ROM устройство от модема, это нормально, ничего с ним делать
  не нужно, modeswitch не требуется).
- Android **не поднимает интерфейс сам** — это надо сделать руками через adb.

## 2. Доступ к ADB

adbd на этой прошивке уже слушает TCP **5555** и работает **от root** без
дополнительного `su` — `adb shell` сразу даёт root-шелл.

```bash
adb connect <ip-головы>:5555   # если голова уже в вашей сети/по wifi
# или просто по USB-кабелю, если voltage/data кабель к голове подключён
adb devices
adb shell id     # ожидаем uid=0(root)
```

Если `adb connect` завис или пишет `offline` — обычно помогает:

```bash
adb disconnect <ip-головы>:5555
adb connect <ip-головы>:5555
```

## 3. Поднять модем как WAN

Проще всего одной строкой прямо в интерактивной сессии:

```bash
adb shell
```

и внутри (уже root):

```sh
# 1. найти интерфейс модема (на случай если имя не eth1)
for d in /sys/class/net/*; do
    echo "$d: $(cat $d/address 2>/dev/null)"
done
# ищем строку с 34:4b:50:00:00:00 -> это и есть IF, обычно eth1

IF=eth1
ip link set $IF up

# подождать carrier (несущую) перед DHCP
i=0
while [ $i -lt 30 ]; do
    [ "$(cat /sys/class/net/$IF/carrier 2>/dev/null)" = "1" ] && break
    sleep 1; i=$((i+1))
done

# busybox udhcpc здесь без default-скрипта -> адрес и маршрут применяем сами
LEASE=$(busybox udhcpc -i $IF -q -n -f 2>&1)
ADDR=$(echo "$LEASE" | sed -n 's/.*lease of \([0-9.]*\) obtained from \([0-9.]*\).*/\1/p' | tail -1)
GW=$(echo "$LEASE" | sed -n 's/.*lease of \([0-9.]*\) obtained from \([0-9.]*\).*/\2/p' | tail -1)

# запасные значения, если парсинг не сработал (наблюдались ранее на этом модеме)
[ -n "$ADDR" ] || ADDR=192.168.0.178
[ -n "$GW" ]   || GW=192.168.0.1

ip addr replace $ADDR/24 dev $IF
ip route replace default via $GW dev $IF metric 10

echo "eth1 up: $ADDR via $GW"
```

Проверка, что модем реально даёт интернет на уровне ядра:

```bash
adb shell ping -c3 8.8.8.8
```

Если пинги идут — WAN поднят. На этом этапе сама Android-система (и приложения)
ещё может считать, что интернета нет — см. следующий шаг.

## 4. Настройка приоритета сети (чтобы Android и приложения реально это признали)

Вендор держит в `ip rule` десять правил `9990-9999: from all lookup main`,
которые идут **раньше** любых fwmark-правил — то есть маршрутизация трафика
приложений уже и так идёт через модем автоматически, отдельно ничего
переключать не нужно. Единственная проблема — DNS призрачной TBOX-сети, из-за
которой Android считает сеть невалидированной.

Узнать текущие параметры призрачной сети и шлюз модема:

```bash
adb shell "dumpsys connectivity | grep -m1 'type: Tbox'"
adb shell "ip route show table main | grep default"
```

В строке `type: Tbox` ищите `InterfaceName: <iface>` и `DnsAddresses: [ /<dns> ]`
(обычно `vlan72` и `192.168.72.1`). Адрес самой призрачной сети:

```bash
adb shell "ip -4 addr show vlan72"
```

Дальше подставьте реальные значения (или используйте дефолты, если dumpsys
ничего не дал — они наблюдались стабильно на этой прошивке):

```sh
GW=192.168.0.1          # шлюз модема, из шага выше
TBOX_DNS=192.168.72.1   # DNS призрачной сети
TBOX_SRC=192.168.72.4   # адрес призрачной сети (vlan72)
IF=eth1                 # интерфейс модема

# если этот DNS уже отвечает - ничего не трогать (правила уже стоят
# или вернулся настоящий TBOX)
if ! timeout 6 busybox nslookup connectivitycheck.gstatic.com "$TBOX_DNS" >/dev/null 2>&1; then
    iptables -w 10 -t nat -A OUTPUT -d $TBOX_DNS -p udp --dport 53 -j DNAT --to-destination $GW:53
    iptables -w 10 -t nat -A OUTPUT -d $TBOX_DNS -p tcp --dport 53 -j DNAT --to-destination $GW:53
    # после DNAT пакет сохраняет исходный src (адрес vlan72), модем на него
    # не ответит без MASQUERADE
    iptables -w 10 -t nat -A POSTROUTING -s $TBOX_SRC -o $IF -j MASQUERADE
    echo "nat-правила добавлены"
else
    echo "DNS уже отвечает, правила не нужны"
fi
```

## 5. Проверка результата

```bash
adb shell "dumpsys connectivity | grep -A2 '^Active default network'"
adb shell "nslookup ya.ru"
adb shell "ping -c3 ya.ru"
```

Ожидается: активная сеть `VALIDATED`, `Score{50}`, DNS резолвится, пинг по
имени идёт. NTP и обычные приложения после этого должны увидеть интернет.

## Важно

- **Всё это временно, до перезагрузки.** После ребута головы адрес/маршрут на
  `eth1` и nat-правила сбрасываются — последовательность (шаги 3-4) нужно
  повторить заново.
- **Ничего не удаляем автоматически.** Если шлюз модема когда-нибудь сменится,
  старое DNAT-правило на прежний `GW` останется и будет мешать — проверить
  `iptables -w 10 -t nat -S OUTPUT | grep 53` и решить, что с ним делать, вручную.
- `/` на этой прошивке read-only (dm-verity enforcing) — все команды выше
  работают только с runtime-состоянием (routing, netfilter), ничего не пишут
  на системный раздел, поэтому ребут откатывает их сам по себе без каких-либо
  действий с вашей стороны.
